# 고객사에 처음 투입되면 어떻게 적응하겠습니까?
+ 먼저 기존 시스템과 업무 프로세스를 파악하고, 담당자에게 필요한 부분을 질문하면서 빠르게 업무를 익히겠습니다.

# 고객사에서 커뮤니케이션할 때 가장 중요하다고 생각하는 것은?
+ 상대방이 원하는 내용을 정확히 이해하고, 진행 상황이나 문제를 늦지 않게 공유하는 것이라고 생각합니다.

# 고객사 담당자와 의견이 다르면 어떻게 하겠습니까?
+ 제 의견을 근거와 함께 설명하되, 최종적으로는 프로젝트 요구사항과 고객사의 의견을 기준으로 조율하겠습니다.

# 고객사에서 혼자 또는 소수 인원으로 투입된다면 어떻게 하겠습니까?
+ 우선 기존 문서와 코드를 통해 업무를 파악하고, 모르는 부분은 정리해서 담당자에게 질문하며 독립적으로 업무할 수 있도록 하겠습니다.

# 처음 사용하는 기술이 프로젝트에 사용된다면?
+ 기본 개념과 기존 코드를 먼저 파악한 뒤 작은 기능부터 직접 적용하면서 빠르게 익히겠습니다.

# 고객사의 요구사항을 정확히 이해하지 못했다면?
+ 제가 이해한 내용을 먼저 정리해서 확인받고, 필요한 부분을 질문해 요구사항을 정확히 파악하겠습니다.

# 기존 코드를 처음 유지보수하게 된다면 어떻게 접근하겠습니까?
+ 전체 구조와 실행 흐름을 먼저 파악하고, 관련 기능의 코드를 따라가면서 수정 범위를 확인한 후 작업하겠습니다.

# 업무가 익숙하지 않아 일정이 늦어질 것 같다면?
+ 혼자 계속 지연시키기보다 현재 진행 상황과 예상 문제를 미리 공유하고, 필요한 도움을 요청해 일정에 맞추겠습니다.

# 고객사에서 업무 외 요청을 받으면?
+ 우선 요청 내용을 정확히 확인하고, 현재 업무와 일정에 미치는 영향을 판단한 뒤 담당자와 우선순위를 조율하겠습니다.

# 고객사 환경과 회사에서 사용하던 개발 방식이 다르면?
+ 고객사의 개발 규칙과 프로세스를 익히고 그에 맞춰 개발하겠습니다.
