# Java / Spring Backend 면접 단골 질문 정리

## 1. Java

1. **Java의 특징은?**  
   객체지향 · JVM · GC · 플랫폼 독립성

2. **JVM이란?**  
   `.class` 실행 환경 → ClassLoader → 메모리 → 실행

3. **Java 컴파일 과정은?**  
   `.java → javac → .class → JVM → 실행`

4. **Stack / Heap / Method 영역 차이는?**  
   Stack: 지역변수·호출스택 / Heap: 객체 / Method: 클래스·static 정보

5. **GC란?**  
   Heap의 불필요 객체 회수 → Stop-The-World 발생 가능

6. **final / finally / finalize 차이는?**  
   final: 변경 제한 / finally: 예외 후 실행 / finalize: GC 관련 메서드

7. **static이란?**  
   클래스에 귀속 → 객체 생성 없이 사용

8. **Overloading / Overriding 차이는?**  
   Overloading: 같은 이름·다른 파라미터 / Overriding: 부모 메서드 재정의

9. **추상 클래스와 인터페이스 차이는?**  
   추상 클래스: 상태·구현 가능 / 인터페이스: 계약 중심

10. **String이 불변 객체인 이유는?**  
    보안 · String Pool · HashCode 캐싱 · Thread Safe

11. **String / StringBuilder / StringBuffer 차이는?**  
    String: 불변 / Builder: 가변·빠름 / Buffer: 가변·동기화

12. **==와 equals() 차이는?**  
    `==`: 참조 비교 / `equals()`: 논리적 값 비교

13. **HashMap의 중복 판단 과정은?**  
    `hashCode()` → `equals()`

14. **ArrayList vs LinkedList?**  
    ArrayList: 조회 유리 / LinkedList: 삽입·삭제 유리

15. **List / Set / Map 차이는?**  
    List: 순서·중복 / Set: 중복X / Map: Key-Value

16. **Generic이란?**  
    타입 안정성 확보 + 형변환 감소

17. **Checked / Unchecked Exception?**  
    Checked: 컴파일 시 처리 강제 / Unchecked: RuntimeException 계열

18. **try-with-resources란?**  
    `AutoCloseable` 자원 자동 해제

19. **불변 객체의 장점은?**  
    Thread Safe · Side Effect 감소 · 상태 관리 용이

20. **synchronized란?**  
    임계영역에 대한 동시 접근 제어

21. **Reflection이란?**  
    런타임에 클래스·필드·메서드 정보 접근

22. **Singleton이란?**  
    인스턴스를 하나만 생성해 공유하는 패턴

23. **SOLID란?**  
    객체지향 설계 원칙 5가지


## 2. Spring Core

24. **Spring Framework 핵심은?**  
    IoC · DI · AOP

25. **IoC란?**  
    객체 생성·생명주기 제어권을 개발자 → 컨테이너

26. **DI란?**  
    의존 객체를 외부에서 주입 → 결합도 감소

27. **DI 방식과 권장 방식은?**  
    생성자 · Setter · Field → **생성자 주입**

28. **Spring Bean이란?**  
    Spring IoC Container가 관리하는 객체

29. **Bean 등록 방법은?**  
    `@Component` 계열 / `@Configuration + @Bean`

30. **Bean LifeCycle은?**  
    생성 → DI → 초기화 → 사용 → 소멸

31. **Spring Bean 기본 Scope는?**  
    Singleton

32. **Prototype Bean이란?**  
    요청할 때마다 새로운 Bean 생성

33. **Spring Singleton과 일반 Singleton 차이는?**  
    Spring Container가 객체 생성·관리 → 직접 구현보다 유연

34. **Spring Boot vs Spring Framework?**  
    Boot: Auto Configuration + Starter + Embedded Server

35. **AOP란?**  
    공통 관심사 분리 → 로깅·트랜잭션·보안

36. **Filter vs Interceptor?**  
    Filter: Servlet/Web Container / Interceptor: Spring MVC

37. **@RequestBody / @RequestParam / @ModelAttribute?**  
    Body JSON / Query·Parameter / 요청값 객체 바인딩

38. **Lombok은 언제 코드를 생성하나?**  
    컴파일 단계 Annotation Processing


## 3. Spring MVC / Servlet

39. **Servlet이란?**  
    Java 기반 웹 요청·응답 처리 기술

40. **Servlet 동작 흐름은?**  
    Request → Servlet Container → Servlet → `service()` → `doGet/doPost()` → Response

41. **MVC란?**  
    Model · View · Controller로 역할 분리

42. **Spring MVC 요청 흐름은?**  
    `DispatcherServlet → HandlerMapping → HandlerAdapter → Controller → ViewResolver`

43. **DispatcherServlet 역할은?**  
    MVC 요청 처리의 Front Controller

44. **HandlerMapping 역할은?**  
    요청 URL → Controller/Handler 매핑

45. **HandlerAdapter 역할은?**  
    Handler를 실제 호출


## 4. Transaction / JPA

46. **@Transactional 동작 원리는?**  
    AOP Proxy → 메서드 전후 Transaction 처리

47. **@Transactional Self Invocation 문제는?**  
    같은 객체 내부 호출 → Proxy 우회 → Transaction 적용 X

48. **Transaction Propagation이란?**  
    기존 Transaction 참여 여부 결정

49. **Propagation 기본값은?**  
    `REQUIRED` → 기존 Transaction 참여, 없으면 생성

50. **@Transactional(readOnly=true)를 사용하는 이유?**  
    조회 전용 명시 + 변경 감지 부담 감소

51. **JPA N+1이란?**  
    1번 조회 후 연관 데이터 때문에 N번 추가 쿼리 발생

52. **N+1 해결 방법은?**  
    Fetch Join · EntityGraph 등

53. **JPA에서 복잡한 쿼리는?**  
    JPQL / QueryDSL

54. **JPA와 SQL을 직접 사용하는 상황은?**  
    단순 CRUD → JPA / 복잡·동적 쿼리 → QueryDSL 등


## 5. Database

55. **Index란?**  
    조회 성능 향상 자료구조 → 쓰기·저장공간 비용 증가

56. **B+Tree Index 특징은?**  
    정렬된 구조 + 범위 검색에 유리

57. **Clustered / Non-Clustered Index?**  
    Clustered: 데이터 정렬 구조와 연결 / Non-Clustered: 별도 Index

58. **정규화란?**  
    데이터 중복 최소화·무결성 향상

59. **반정규화란?**  
    조회 성능 등을 위해 중복 허용

60. **SQL 실행 순서는?**  
    `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY`

61. **SQL Injection 방어 방법은?**  
    Prepared Statement · 파라미터 바인딩

62. **SQL Optimizer란?**  
    SQL 실행 계획을 결정하는 DBMS 구성요소


## 6. Web / Backend

63. **WAS와 Web Server 차이는?**  
    WS: 정적 콘텐츠 / WAS: 애플리케이션·비즈니스 로직

64. **WAS의 역할은?**  
    HTTP 요청 처리 + 애플리케이션 실행

65. **REST API란?**  
    HTTP Method + URI로 Resource를 표현·조작

66. **GET / POST 차이는?**  
    GET: 조회·Query / POST: 생성·Body

67. **HTTP가 Stateless인 이유는?**  
    요청 간 상태를 기본적으로 유지하지 않음

68. **Cookie / Session 차이는?**  
    Cookie: Client 저장 / Session: Server 저장

69. **JWT란?**  
    Claim을 포함한 서명된 Token 기반 인증

70. **HTTP / HTTPS 차이는?**  
    HTTPS = HTTP + TLS 암호화

71. **CORS란?**  
    다른 Origin 간 브라우저 요청 제한 정책

72. **CSRF란?**  
    인증된 사용자의 권한을 악용한 위조 요청

73. **XSS란?**  
    악성 Script를 사용자 브라우저에서 실행시키는 공격

74. **SSRF란?**  
    서버가 공격자가 의도한 주소로 요청하도록 유도

75. **Cache란?**  
    자주 사용하는 데이터를 빠른 저장소에 저장해 성능 향상


## 7. 동시성 / 서버

76. **Process와 Thread 차이는?**  
    Process: 독립 메모리 / Thread: Process 자원 공유

77. **Thread Pool이란?**  
    Thread를 미리 생성·재사용해 생성 비용 감소

78. **Deadlock이란?**  
    서로 Lock을 기다리며 무한 대기

79. **동시성 문제 해결 방법은?**  
    synchronized / DB Lock / Optimistic·Pessimistic Lock

80. **대용량 트래픽 대응 방법은?**  
    Scale-Up / Scale-Out + Cache + DB 최적화

81. **Scale-Up vs Scale-Out?**  
    Scale-Up: 서버 성능 향상 / Scale-Out: 서버 수 증가

82. **MSA란?**  
    서비스를 독립적인 작은 서비스로 분리하는 아키텍처


## 8. Network

83. **웹 요청 전체 흐름은?**  
    URL → DNS → TCP → HTTP Request → Server → Response → Rendering

84. **TCP 3-Way Handshake란?**  
    `SYN → SYN/ACK → ACK`

85. **Router란?**  
    서로 다른 네트워크 간 패킷 전달

86. **NAT란?**  
    사설 IP ↔ 공인 IP 변환

87. **VPN이란?**  
    공용망에서 암호화된 사설 통신망 구성
